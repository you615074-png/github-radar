Where the milliseconds go back to you

Three ways developers put a 2.5 ms container start to work.

🧪

A tight inner loop

You run the test suite 200 times a day. When start-and-exit costs about 2.5 ms, docker run --rm feels like calling a local binary instead of a two-second pause before every run. 

docker --context kiri run --rm \
  -v "$PWD":/app node:22 npm test
🚚

Switch in one command

kiri import brings images, volumes and containers over from Docker Desktop or OrbStack. Your Compose files, buildx and docker login keep working, because Kiri speaks the Docker Engine API. 

kiri import
kiri ps
☸️

Kubernetes and Linux machines

A single-node cluster that shows up as its own kubectl context, plus Linux machines with local <name>.kiri.local domains and HTTPS from Kiri's own certificate authority. 

kiri k8s start
kiri machine create dev --distro ubuntu
