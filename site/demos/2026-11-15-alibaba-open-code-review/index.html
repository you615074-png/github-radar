Where teams use it

Three ways it earns its seat

Same engine, three workflows — a PR gate, an audit tool for old code, and a CI step that costs a fraction of a general-purpose agent.

🛡️

The PR gate for a lean team

Install on six repos. Every pull request gets the same review rigor as a staff engineer — comments pinned to the exact changed line, so nobody hunts for the bug.

Typical: ~20s per PR · 5.2 defects per 100 changed lines

🗂️

Audit the code nobody touches

No meaningful diff? Point it at a directory and it reviews whole files — find the thread-safety and NPE landmines in that 2016 service before you refactor it.

Whole-file scan · same ruleset, no PR required

⚙️

CI without the model bill

Keep your pipeline. Post the review back as a GitHub check run, or block the merge on critical findings only. Roughly one-ninth the tokens of a general-purpose agent.

Deterministic steps · agent only where it helps
